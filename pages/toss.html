MIPS 마이크로커널 운영체제

2024.03 – 2024.07 · 1인 개발
OS Kernel 전체 구현 · 7단계 커널 완주 · Lock-free IPC race condition 해결

MIPS 아키텍처 위에서 부팅, 가상 메모리, 프로세스, 시스템콜, IPC, 파일 시스템까지 OS 핵심 구성요소를 직접 구현하며 커널 레벨 동시성 제어 원리를 체득했습니다.

구현
  • 2단계 페이지 테이블과 TLB Fast Refill 핸들러를 어셈블리로 최적화하고, Copy-on-Write 기반 fork()를 구현해 프로세스 생성 시 메모리 오버헤드를 낮췄습니다.
  • 사용자 공간에서 동작하는 FS 서버 프로세스와 공유 페이지 기반 Pipe IPC를 구현해 커널과 파일 시스템을 물리적으로 분리했습니다.
문제

Pipe IPC 구현 중 스케줄링 타이밍에 따라 열린 파이프를 닫힌 것으로 오인하는 동시성 문제가 발생했습니다. 인터럽트 비활성화 대신 근본 원인인 매핑 순서 의존성을 분석했습니다.

해결

close()와 dup() 호출 시 페이지 map/unmap 순서를 재배치해 pageref(fd) ≤ pageref(pipe) 불변식이 항상 유지되도록 설계했습니다. 그 결과 락 없이도 안정적인 동시성 제어를 구현했습니다.

기여

부팅부터 셸까지 전 단계를 1인 단독 설계 및 구현했습니다. 특히 코드 실행 순서 재배치만으로 불변식을 강제하는 구조적 해결책을 직접 도출했습니다.

SysY 언어 컴파일러 프론트엔드 & VM

2024.10 – 2025.01 · 1인 개발
Lexer / Parser / Symbol Table / P-Code VM 구축 · a-m 전 에러 범주 처리 · Fault-Tolerant 파서

SysY 언어의 Lexer, 재귀 하향 Parser, Symbol Table, P-Code VM 전 과정을 C++17로 구현하고, 구문 오류가 발생해도 파싱을 중단하지 않는 결함 허용 파서를 설계했습니다.

구현
  • 모호성을 해결하는 재귀 하향 파서를 설계하고, 스코프 체인을 지원하는 심볼 테이블로 함수 시그니처 불일치와 중복 선언을 컴파일 타임에 진단했습니다.
  • 단일 파일 구조를 Lexer, Parser, SymbolTable, ErrorHandler, Interpreter 5개 모듈로 분리해 에러 복구 로직의 변경 영향 범위를 줄였습니다.
문제

세미콜론 누락 에러 복구 시 토큰 포인터가 과도하게 이동해 정상 구문까지 연쇄적으로 오류로 판정하는 문제가 발생했습니다.

해결

에러를 파싱 중단 사유가 아닌 문맥 복귀 신호로 재정의하고, 직전 유효 토큰 위치인 mLastNonT를 기록해 파서를 중단하지 않고 정상 흐름으로 복구하도록 개선했습니다.

학습

견고한 시스템은 정상 입력뿐 아니라 비정상 입력에서도 상태를 잃지 않아야 한다는 점을 체득했습니다. 이후 백엔드 API 예외 처리 구조를 설계할 때 같은 원칙을 적용했습니다.

한국인 1명, 중국인 3명, 교환학생 1명으로 구성된 다국적 팀에서 PostgreSQL, Elasticsearch, Redis, MinIO를 통합한 학술 성과 검색 및 분석 백엔드를 구축했습니다.

구현
  • 팀원 간 OS와 DB 버전 파편화로 인한 인프라 기동 실패를 줄이기 위해 Docker Compose 기반 통합 개발 환경을 구축하고 README와 RFC 문서화를 주도했습니다.
  • 검색 성능 요구에 맞춰 PostgreSQL과 Elasticsearch를 함께 운용하고, Redis와 MinIO를 연결해 데이터 조회와 파일 저장 흐름을 분리했습니다.
문제

개발자마다 API 응답 구조가 달라 프론트엔드에서 파싱 오류가 반복됐습니다. 문서화와 구두 합의만으로는 런칭 기한이 가까워질수록 휴먼 에러가 재발했습니다.

해결

Spring의 ResponseBodyAdvice를 구현해 컨트롤러 반환값을 항상 {code, message, data} 구조로 자동 래핑했습니다. 규약 준수를 사람에게 맡기지 않고 아키텍처 계층에서 강제해 API 파싱 오류를 0건으로 수렴시켰습니다.

협업

Vue와 React, Huawei Cloud와 AWS 선택 이견이 있을 때 더미 데이터 10만 건으로 RDBMS LIKE 연산과 Elasticsearch 응답 속도를 ms 단위로 비교해 데이터 기반 합의를 이끌었습니다.

CareLink — 실시간 노인 심전도(ECG) 진단 플랫폼

2025.10 – 2026.03 · 1인 개발 / 졸업논문
3-Tier 아키텍처 · AI 추론 서버 · ECG 진단 AUC 92.52% · TPS 66 AWS 운영

환자와 보호자를 연결하는 모바일 앱과 실시간 ECG AI 진단 기능을 React Native, Spring Boot, FastAPI 3-Tier로 분리해 제한된 AWS 인프라에서도 운영 가능한 구조로 구현했습니다.

구현
  • PTB-XL 데이터셋 기반으로 12-lead 진폭 특성 36차원을 설계하고 CNN-CBAM-GRU 모델에 주입해 Macro AUC 92.52%를 달성했습니다.
  • 비즈니스 로직은 Spring Boot, AI 추론은 FastAPI로 분리하고 JWT 인증, 자동 로그아웃, Cache-First 전략으로 앱 응답성을 개선했습니다.
문제

AI 컨테이너와 백엔드를 동시에 구동하면 1GB RAM EC2에서 OOM이 반복됐습니다. JVM 힙 튜닝만으로는 절대적인 메모리 부족을 해결할 수 없었습니다.

해결

로컬과 CI에서 이미지를 빌드해 레지스트리에 push하고, 서버는 Pull-only로만 운영하는 전략으로 전환했습니다. Docker mem_limit으로 컨테이너별 자원을 격리하고 AI 컨테이너는 profile로 분리해 필요할 때만 기동하도록 개선했습니다.

기여

프론트, 백엔드, AI 추론 3개 레이어의 설계·구현·배포 전 과정을 1인 단독 수행했습니다. 모델 아키텍처 선정, 피처 설계, 손실 함수 조정, 추론 서버 배포까지 데이터 파이프라인 전체를 책임졌습니다.

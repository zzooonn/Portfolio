# 포트폴리오 평가 및 수정 기록

작성일: 2026-10-02

## 채용 담당자 관점의 핵심 평가

원본의 문제는 흰 배경이나 폰트 자체보다 정보의 우선순위였다. 서로 다른 프로젝트 네 개가 같은 글 목록으로 보여, 짧은 시간 안에 대표작과 개발자의 강점을 구별하기 어려웠다. 가장 오래된 OS 과제가 첫 번째여서 최근 서비스 개발 경험도 뒤로 밀렸다.

문제 해결 과정과 본인 기여를 구분한 내용은 유지할 가치가 있다. 특히 팀 전체의 아키텍처와 본인이 구현한 범위를 구분하고, 서로 다른 조건의 성능 측정을 개선율처럼 포장하지 않은 점은 신뢰도를 높인다. 이 장점이 첫 화면과 요약 카드에서도 드러나도록 구조를 바꿨다.

## 실제 반영 사항

1. **첫 화면의 개발자 소개 구체화**
   - 시스템 이해와 서비스 예외 상황 처리라는 중심 메시지로 소개를 정리했다.
   - 첫 소개의 개발 경험은 유지하고, 추가했던 세 칸의 영문 기술 배너는 제거했다.
   - 특정 지원 직무를 확정하지 않은 상태에서 백엔드·시스템 경험을 중심으로 읽히도록 했다.

2. **대표작과 프로젝트 순서**
   - CareLink → 학술 성과 공유 플랫폼 → SysY 컴파일러 → MIPS OS 순으로 변경했다.
   - 기존 종료일 기준 최신순이며, CareLink를 넓은 대표작 카드로 강조했다.
   - 학력·교육과 어학 성적도 최신순으로 정리했다. 진행 중 교육은 가장 먼저 표시했다.

3. **프로젝트별 시각 자료**
   - CareLink: 앱 → Spring Boot → FastAPI/PyTorch와 Spring Boot ↔ PostgreSQL 관계를 보여주는 구조 요약.
   - 학술 플랫폼: 프로토타입 이미지를 제거하고 저장소에 근거한 서비스 구조도로 교체했다. Vue 3 → Spring Boot에서 PostgreSQL·Elasticsearch·Redis·MinIO로 각각 연동하는 구조를 표시했다. 백엔드 안에는 본인 담당 범위를 명시했다.
   - SysY: 소스 → 파서/P-Code → 스택 VM의 구현 흐름.
   - MIPS OS: 사용자 프로그램/IPC → 커널 → 가상메모리의 계층 요약.
   - 자료에 없는 앱 실행 화면과 성능 수치는 새로 만들지 않았다.

4. **가독성과 디자인**
   - Pretendard 본문 폰트는 유지했다.
   - 이름 42px, 소개 23px, 프로젝트 제목 21px, 본문 16~17px를 중심으로 원문에 가까운 크기를 사용했다.
   - 작은 보조 문구의 크기를 높이고 본문을 16~17px 중심으로 조정했다.
   - 사용자 요청에 따라 전체를 흰색 단색 바탕으로 되돌렸다. 녹색 배경·그라데이션·사진 그림자·제목 장식·둥근 카드 테두리를 제거하고, 원문의 문서형 배치와 얇은 구분선을 사용했다.
   - 대표작은 설명과 구조를 함께 보여주고, 나머지는 설명과 미리보기를 구분했다.
   - 상세 설명은 펼쳐 읽는 방식을 유지해 처음부터 긴 기술 문서를 읽게 하지 않았다.

5. **탐색과 접근성**
   - 프로젝트 전체를 감싸던 버튼을 독립적인 상세 열기 버튼으로 변경했다.
   - 학술 플랫폼의 프로젝트 저장소 링크를 요약에 추가했다.
   - 키보드 포커스, 3개 언어의 새 문구, 메뉴의 접근성 이름을 정리했다.
   - PDF 저장 버튼을 추가하고 인쇄 후 펼침 상태와 버튼 문구가 복원되도록 했다.
   - 잘못된 저장 언어 값으로 초기화가 중단되지 않도록 보완했다.
   - 모바일에서는 카드와 다이어그램이 세로로 전환되도록 스타일을 작성했다.

## 남아 있는 중요한 보완점

| 우선순위 | 보완할 내용 | 필요한 근거 |
|---|---|---|
| 높음 | CareLink 실제 실행 화면 또는 30~60초 시연 | 앱에서 직접 캡처한 화면, 동작 범위와 데모 데이터 안내 |
| 높음 | CareLink·SysY·MIPS의 프로젝트별 코드 링크 | 실제 공개 저장소 주소, 실행 방법과 본인 구현 범위 |
| 높음 | CareLink의 상태 코드 전달과 모델 버전 차이 | 서비스 코드 수정 및 재검증. 이번 HTML 수정으로 해결한 것으로 표시하지 않음 |
| 선택 | 학술 플랫폼의 실제 실행 화면 | 필요하면 실제 동작을 촬영한 자료를 별도로 추가. 현재 요약에는 서비스 구조도를 사용 |
| 지원 시 | 지원 직무별 첫 소개 조정 | 백엔드 또는 시스템/임베디드 채용공고에 맞는 경험 우선순위 |

성과와 미해결 문제에 대한 원래 설명은 보존했다. 이번 작업은 포트폴리오 표현을 개선한 것이며, 소개된 프로젝트의 서버 코드나 모델을 수정한 작업은 아니다.

## 검증 범위와 제한

- HTML 태그 구조, 중복 ID, 내부 이동 링크, 펼침 버튼의 연결 대상, 이미지·스타일 파일 존재 여부를 확인했다.
- JavaScript 구문과 한국어·영어·중국어 번역 키를 확인했다.
- DOM을 모사한 검증에서 네 프로젝트 열기·닫기, 메뉴 열기·닫기, 정보 가리기, 프로젝트 직접 링크, 인쇄 전후 상태 복원, 잘못된 언어 설정 복구를 확인했다.
- 브라우저 보안 정책이 로컬 파일 URL 접근을 거부해 실제 브라우저 화면, 모바일 배치, PDF 페이지 나눔은 시각적으로 검증하지 못했다. 실제 화면에서의 최종 확인이 필요하다.
- 이전 대화에서 비교했다는 공개 포트폴리오 저장소의 목록은 이번 요청에 없었다. 확인하지 않은 저장소를 참고 목록으로 만들어 넣지 않았다.

## 파일

- `index.html`: 수정한 메인 페이지.
- `assets/portfolio.css`: 레이아웃과 반응형·인쇄 스타일.
- 학술 플랫폼 프로토타입 이미지 파일은 보관하되 페이지에서는 사용하지 않는다.
- `수정.md`: 평가, 실제 반영 내용, 후속 보완과 검증 범위.
- 원본 HTML은 적용 전 `backups/`에 별도로 보관한다.


## 흰색 디자인 및 학술 플랫폼 구조도 재수정

- 사용자가 지정한 공개 저장소의 [README](https://github.com/saitewasreset/BUAA-SSAD-2025-Project-Group1-AcademicPlatform)를 확인해 Vue 3/TypeScript, Spring Boot/Java와 PostgreSQL·Elasticsearch·Redis·MinIO 구성을 반영했다.
- [백엔드 README](https://github.com/saitewasreset/BUAA-SSAD-2025-Project-Group1-AcademicPlatform/blob/dev/backend/README.md)와 제공된 로컬 소스도 대조했다. 별도 벡터 서버와 백엔드 내부 임베딩 모델을 함께 그린 기존 상세 SVG는 제거하고 검증 가능한 주요 구성만 설명했다.
- 각 저장소와 검색·캐시 서비스는 직렬 처리 순서가 아니라 Spring Boot의 독립적인 연동 대상이다. 본인이 모든 인프라를 구현한 것으로 표현하지 않았다.
- CareLink 구조도도 동일한 흰색 바탕과 얇은 선으로 통일했다. 화면 조작과 최신순 프로젝트 정렬은 유지했다.
- 이번 수정의 확인 범위는 HTML 구조, JavaScript 구문, 번역 항목 및 파일 연결이다. 실제 브라우저 배치는 별도 시각 검증이 필요하다.


## Pinterest에서 착안한 프로젝트 카드 구성

- 흰색 단색 배경, 검정·회색 글씨와 Pretendard 폰트를 유지했다.
- 프로젝트를 2열 보드에 배치하고, 구조도를 위에, 제목·역할·결과를 아래에 놓았다. 내용 길이에 맞춰 카드 높이가 달라진다.
- 카드 모서리는 부드럽게 처리하고 얇은 경계선으로 구분했다. 그라데이션·컬러 면·강한 그림자·장식 애니메이션은 추가하지 않았다.
- 40~50대 채용 담당자의 읽기 편의성을 고려해 프로젝트 제목은 22~23px, 요약은 16~17px, 역할과 버튼은 14~15px를 사용했다.
- 프로젝트를 열면 보드 전체 폭으로 확장하며, 다른 열린 프로젝트는 닫힌다. 상세 끝에도 닫기 버튼을 두고 닫을 때 원래 버튼으로 키보드 포커스를 돌려준다.
- 좁은 화면에서는 1열로 전환한다. DOM 순서와 키보드 탐색 순서는 최신순을 유지하고, 인쇄에서는 원래 문서처럼 세로로 출력한다.
- 레이아웃 코드는 글꼴 로딩, 언어 변경, 상세 펼침, 화면 크기 변경에 따른 카드 높이를 다시 계산한다. JavaScript를 사용할 수 없는 경우 기본 2열/1열 그리드가 유지된다.
- 학술 플랫폼의 저장소 기반 구조도와 본인 기여 표시, 성능·미해결 문제의 설명은 보존했다.
- 실제 브라우저 시각 검증은 로컬 파일 접근 제한으로 수행하지 못했다. 이번 확인은 HTML 구조, 번역, 상호작용과 카드 배치 계산의 코드 검증에 한한다.

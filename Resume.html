MIPS 마이크로커널 운영체제

2024.03 – 2024.07 · 1인 개발
OS Kernel 전체 구현 · 7단계 커널 완주 · Lock-free IPC race condition 해결

MIPS 아키텍처 위에서 부팅, 가상 메모리, 프로세스, 시스템콜, IPC, 파일 시스템까지 OS 핵심 구성요소를 직접 구현하며, 추상화 아래에서 동시성과 메모리가 실제로 어떻게 작동하는지 끝까지 파헤쳤습니다.

구현
  • 2단계 페이지 테이블과 TLB Fast Refill 핸들러를 어셈블리로 최적화하고, Copy-on-Write 기반 fork()를 구현해 프로세스 생성 시 메모리 오버헤드를 낮췄습니다.
  • 사용자 공간에서 동작하는 FS 서버 프로세스와 공유 페이지 기반 Pipe IPC를 구현해 커널과 파일 시스템을 물리적으로 분리했습니다.
문제

Pipe IPC 구현 중 스케줄링 타이밍에 따라 열린 파이프를 닫힌 것으로 오인하는 동시성 문제가 발생했습니다. 인터럽트 비활성화로 임시 봉합하는 대신 근본 원인인 매핑 순서 의존성까지 내려가 분석했습니다.

해결

close()와 dup() 호출 시 페이지 map/unmap 순서를 재배치해 pageref(fd) ≤ pageref(pipe) 불변식이 항상 유지되도록 설계했고, 락 없이도 안정적인 동시성 제어를 구현했습니다.

기여

부팅부터 셸까지 전 단계를 1인 단독 설계 및 구현했고, 특히 코드 실행 순서 재배치만으로 불변식을 강제하는 구조적 해결책을 직접 도출했습니다.

SysY 언어 컴파일러 프론트엔드 & VM

2024.10 – 2025.01 · 1인 개발
Lexer / Parser / Symbol Table / P-Code VM 전 파이프라인 구축 · a~m 전 에러 범주 처리 · Fault-Tolerant 파서

SysY 언어의 Lexer, 재귀 하향 Parser, Symbol Table, P-Code 생성기, 스택 머신 VM까지 컴파일러 전체 파이프라인을 C++17로 직접 구현하고, 구문 오류가 발생해도 파싱을 중단하지 않는 결함 허용 파서를 끝까지 완성했습니다.

구현
  • unordered_map 기반 키워드 판별과 peek() 메커니즘으로 <=·==·&& 등 다중 문자 연산자와 이스케이프 시퀀스 포함 문자열 상수를 일관되게 토큰화했습니다.
  • CompUnit 선행 탐색과 LVal = Exp vs [Exp] 모호성 판별을 갖춘 재귀 하향 파서를 설계하고, 연산자 우선순위 기반 계층적 식 파싱을 구현했습니다.
  • 스코프 ID와 스택 기반 심볼 테이블로 변수 섀도잉, 함수 시그니처 불일치, 상수 재대입, 미선언 식별자 등 의미 오류를 컴파일 타임에 검출했습니다.
  • 산술·논리·분기·반복·함수 호출·배열 인덱싱·I/O를 위한 P-Code 명령어 셋을 직접 설계하고, 이를 실행하는 스택 머신 인터프리터까지 구현했습니다.
문제

세미콜론 누락 케이스를 처리하려고 에러 함수를 추가하면, 기존에 통과하던 정상 파싱까지 깨지는 현상이 반복됐습니다. 단순한 패치로 덮는 대신 원인을 끝까지 추적해보니, parseErrorI/J/K가 검사 함수가 아니라 AdvanceToNextToken()으로 mCurpos를 직접 변경하는 토큰 소비 함수였고, 호출 순서가 조금만 바뀌어도 후속 구문이 엉뚱한 토큰에서 시작하는 구조적 결함이 있었습니다.

해결

에러 함수들을 토큰 소비형(I/J/K), look-ahead형(E), 심볼 등록형(B)으로 먼저 분류했습니다. 그 위에서 에러를 파싱 중단 사유가 아닌 문맥 복귀 신호로 재정의하고, 새 복구 로직은 현재 위치를 저장한 뒤 필요한 토큰만 미리 확인하고 원위치로 되돌리도록 정리했으며, 누락 토큰은 직전 의미 단위(mLastNonT) 기준으로 기록하도록 재설계했습니다.

학습

왜 틀렸는지 끝까지 추적하는 과정이 제 개발 방식임을 이 프로젝트에서 확신했습니다. 상태를 바꾸는 함수와 읽기만 하는 함수를 구분해야 한다는 원칙, 그리고 견고한 시스템은 정상 입력뿐 아니라 비정상 입력에서도 상태를 잃지 않아야 한다는 원칙을 이후 백엔드 API 예외 처리 설계에도 그대로 적용했습니다.

구현
  • 팀원 간 OS와 DB 버전 파편화로 인한 인프라 기동 실패를 줄이기 위해 Docker Compose 기반 통합 개발 환경을 구축하고 README와 RFC 문서화를 주도했습니다.
  • 검색 성능 요구에 맞춰 PostgreSQL과 Elasticsearch를 함께 운용하고, Redis와 MinIO를 연결해 데이터 조회와 파일 저장 흐름을 분리했습니다.
문제

개발자마다 API 응답 구조가 달라 프론트엔드에서 파싱 오류가 반복됐습니다. 문서화와 구두 합의만으로는 런칭 기한이 가까워질수록 휴먼 에러가 재발했고, 사람의 주의에 의존하는 한 끝나지 않는 문제임을 확인했습니다.

협업

Vue와 React, Huawei Cloud와 AWS 선택 이견이 있을 때 더미 데이터 10만 건으로 RDBMS LIKE 연산과 Elasticsearch 응답 속도를 ms 단위로 비교해, 감정이 아닌 데이터로 합의를 이끌어냈습니다.

환자와 보호자를 연결하는 모바일 앱과 실시간 ECG AI 진단 기능을 React Native, Spring Boot, FastAPI 3-Tier로 분리해, 제한된 AWS 인프라에서도 끝까지 운영 가능한 구조로 직접 완성했습니다.

구현
  • PTB-XL 데이터셋 기반으로 12-lead 진폭 특성 36차원을 설계하고 CNN-CBAM-GRU 모델에 주입해 Macro AUC 92.52%를 달성했습니다.

문제

기여

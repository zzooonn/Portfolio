CareLink — AWS EC2/Docker 서비스 운영 검증

2025.10 – 2026.03 · 1인 개발 / 졸업논문
3-Tier 서비스 · AWS EC2 배포 · 컨테이너 자원 제한 · OOM 대응 · TPS 66 측정

모바일 앱, Spring Boot 백엔드, FastAPI AI 추론 서버를 분리한 3-Tier 구조를 AWS EC2와 Docker 기반으로 배포하고, 제한된 서버 자원에서 안정적으로 운영되도록 개선했습니다.

구현
  • Spring Boot 비즈니스 로직과 FastAPI AI 추론 서버를 컨테이너 단위로 분리해 장애 범위와 자원 사용량을 독립적으로 관리할 수 있게 구성했습니다.
  • JWT 인증, 자동 로그아웃, Cache-First 조회 전략을 적용하고 20명 동시 접속 기준 주요 API TPS 56.23~66.41을 측정했습니다.
문제

AI 컨테이너와 백엔드를 동시에 구동하면 1GB RAM EC2에서 OOM이 반복됐습니다. 서버에서 직접 이미지를 빌드하는 방식은 배포 중 서비스 안정성을 떨어뜨렸습니다.

해결

로컬과 CI에서 이미지를 빌드해 레지스트리에 push하고, 서버는 Pull-only로 운영하도록 전환했습니다. Docker mem_limit으로 컨테이너별 자원을 격리하고 AI 컨테이너는 profile로 분리해 필요할 때만 기동하도록 개선했습니다.

운영

성능 수치와 배포 제약을 함께 확인하며 서비스 구동 순서, 컨테이너 자원 제한, 배포 절차를 정리했습니다. 장애를 코드 수정만이 아니라 운영 방식 변경으로 해결한 경험입니다.

학술 성과 공유 플랫폼 — Docker Compose 다중 인프라

5인 팀 프로젝트 · PostgreSQL/Elasticsearch/Redis/MinIO 통합 · 환경 표준화 · API 오류 0건 수렴

다국적 팀에서 Spring Boot 백엔드를 전담하며 PostgreSQL, Elasticsearch, Redis, MinIO를 통합하고, 팀원별 개발 환경 차이를 Docker Compose와 문서화로 정리했습니다.

구현
  • PostgreSQL, Elasticsearch, Redis, MinIO를 Docker Compose로 묶어 로컬 기동 절차를 표준화하고 README와 RFC 문서로 실행 조건을 정리했습니다.
  • 검색 성능 요구에 맞춰 RDBMS와 Elasticsearch를 함께 운용하고, 파일 저장은 MinIO로 분리해 데이터 흐름과 장애 범위를 명확히 했습니다.
문제

팀원마다 OS, DB 버전, 실행 순서가 달라 인프라 기동 실패가 반복됐습니다. 또한 API 응답 구조가 달라 프론트엔드 파싱 오류가 계속 발생했습니다.

해결

협업

Vue와 React, Huawei Cloud와 AWS 선택 이견이 있을 때 더미 데이터 10만 건으로 RDBMS LIKE 연산과 Elasticsearch 응답 속도를 비교해 데이터 기반 합의를 이끌었습니다.

MIPS 마이크로커널 운영체제

2024.03 – 2024.07 · 1인 개발
OS Kernel 전체 구현 · 메모리/프로세스/IPC/파일 시스템 · Lock-free IPC race condition 해결

MIPS 아키텍처 위에서 부팅, 가상 메모리, 프로세스, 시스템콜, IPC, 파일 시스템까지 OS 핵심 구성요소를 직접 구현하며 시스템 엔지니어에게 필요한 내부 동작 감각을 쌓았습니다.

구현
  • 2단계 페이지 테이블과 TLB Fast Refill 핸들러를 어셈블리로 최적화하고, Copy-on-Write 기반 fork()를 구현해 프로세스 생성 비용을 낮췄습니다.
  • 사용자 공간 FS 서버와 공유 페이지 기반 Pipe IPC를 구현해 커널과 파일 시스템을 분리하고, 시스템콜 흐름을 직접 설계했습니다.
문제

Pipe IPC 구현 중 스케줄링 타이밍에 따라 열린 파이프를 닫힌 것으로 오인하는 동시성 문제가 발생했습니다. 인터럽트 비활성화 대신 근본 원인인 매핑 순서 의존성을 분석했습니다.

해결

close()와 dup() 호출 시 페이지 map/unmap 순서를 재배치해 pageref(fd) ≤ pageref(pipe) 불변식이 항상 유지되도록 설계했습니다. 그 결과 락 없이 안정적인 동시성 제어를 구현했습니다.

연결점

메모리, 프로세스, 파일 시스템, IPC를 구현하며 OS 설치와 운영을 단순 사용이 아닌 내부 상태 전이 관점에서 이해하게 됐습니다. 장애 대응 시 커널/프로세스/파일 I/O를 함께 보는 기반이 됩니다.

SysY 언어 컴파일러 프론트엔드 & VM

2024.10 – 2025.01 · 1인 개발
C++17/CMake · Lexer/Parser/Symbol Table/P-Code VM · Fault-Tolerant 파서

SysY 언어의 Lexer, 재귀 하향 Parser, Symbol Table, P-Code VM 전 과정을 C++17과 CMake로 구현하고, 구문 오류가 발생해도 파싱을 중단하지 않는 결함 허용 구조를 설계했습니다.

구현
  • 모호성을 해결하는 재귀 하향 파서를 설계하고, 스코프 체인을 지원하는 심볼 테이블로 함수 시그니처 불일치와 중복 선언을 컴파일 타임에 진단했습니다.
  • 단일 파일 구조를 Lexer, Parser, SymbolTable, ErrorHandler, Interpreter 5개 모듈로 분리하고 CMake 기반 빌드 흐름으로 정리했습니다.
문제

세미콜론 누락 에러 복구 시 토큰 포인터가 과도하게 이동해 정상 구문까지 연쇄적으로 오류로 판정하는 문제가 발생했습니다.

해결

에러를 파싱 중단 사유가 아닌 문맥 복귀 신호로 재정의하고, 직전 유효 토큰 위치인 mLastNonT를 기록해 파서를 중단하지 않고 정상 흐름으로 복구하도록 개선했습니다.

연결점

반복 작업 자동화와 시스템 개발 업무에 필요한 코드 구조화, 빌드 관리, 예외 복구 사고를 쌓았습니다. 정상 흐름만 맞추는 구현보다 비정상 입력과 중간 상태를 견디는 구조를 우선합니다.

CareLink — AI 추론 서버와 모바일 헬스케어 플랫폼

2025.10 – 2026.03 · 1인 개발 / 졸업논문
3-Tier 아키텍처 · FastAPI AI 추론 서버 · Docker 운영 · AWS EC2 · TPS 66 · Macro AUC 92.52%

환자와 보호자를 연결하는 모바일 앱과 ECG AI 진단 기능을 React Native, Spring Boot, FastAPI 3-Tier로 분리했습니다. AI 모델 개발뿐 아니라 제한된 AWS EC2 환경에서 컨테이너를 운영하며 설치, 배포, 장애 대응 관점의 문제를 직접 해결했습니다.

구축
  • Spring Boot 백엔드와 FastAPI AI 추론 서버를 분리하고, Docker 컨테이너 기반으로 서비스별 실행 환경을 구성했습니다.
  • PTB-XL 데이터셋 기반 CNN-CBAM-GRU 모델을 구축하고, 36차원 ECG 피처를 설계해 Macro AUC 92.52%를 달성했습니다.
  • JWT 인증, 자동 로그아웃, Cache-First 전략을 적용해 앱 사용 중 응답성을 개선했습니다.
장애

AI 컨테이너와 백엔드를 동시에 구동하면 1GB RAM EC2에서 OOM이 반복됐습니다. JVM 힙 튜닝만으로는 해결되지 않아 컨테이너 자원과 배포 방식 전체를 점검했습니다.

해결

로컬/CI에서 이미지를 빌드해 레지스트리에 push하고, 서버는 Pull-only로만 운영하도록 전환했습니다. Docker mem_limit과 profile로 자원을 격리해 필요할 때만 AI 컨테이너를 기동했습니다.

운영

부하 테스트로 TPS 66을 측정하고, AI 모델 성능뿐 아니라 P95 레이턴시와 컨테이너 자원 사용량을 함께 확인했습니다. 고객 환경 운영 지원에 필요한 관찰 지표를 의식하며 개선했습니다.

다국적 팀에서 검색·저장·캐시·파일 스토리지를 통합한 백엔드를 담당했습니다. 팀원별 OS와 DB 버전 차이로 개발 환경이 자주 깨지는 문제를 Docker Compose 기반 통합 환경과 문서화로 줄였습니다.

운영
  • PostgreSQL, Elasticsearch, Redis, MinIO를 Docker Compose로 묶어 신규 팀원이 동일한 환경을 빠르게 띄울 수 있도록 구성했습니다.
  • README와 RFC를 정리해 설치 절차, API 규약, 로컬 실행 방법, 인프라 구성 의도를 문서화했습니다.
문제

소통

MIPS 마이크로커널 운영체제

2024.03 – 2024.07 · 1인 개발
OS Kernel 전체 구현 · Virtual Memory · TLB · IPC · File System · 동시성 문제 해결

MIPS 아키텍처 위에서 부팅, 가상 메모리, 프로세스, 시스템콜, IPC, 파일 시스템까지 직접 구현했습니다. Linux/컨테이너 운영 자체는 아니지만, 프로세스·메모리·동시성의 기본 동작을 낮은 수준에서 이해하는 기반이 됐습니다.

구현
  • 2단계 페이지 테이블과 TLB Fast Refill 핸들러를 어셈블리로 최적화하고, Copy-on-Write 기반 fork()를 구현했습니다.
  • 사용자 공간 FS 서버와 공유 페이지 기반 Pipe IPC를 구현해 커널과 파일 시스템을 분리했습니다.
문제

Pipe IPC 구현 중 스케줄링 타이밍에 따라 열린 파이프를 닫힌 것으로 오인하는 동시성 문제가 발생했습니다.

해결

close()와 dup() 호출 시 페이지 map/unmap 순서를 재배치해 pageref(fd) ≤ pageref(pipe) 불변식이 유지되도록 설계했습니다. 외부 락 없이 실행 순서만으로 안정성을 확보했습니다.

의미

장애 대응 시 프로세스, 메모리, 파일 디스크립터, 동시성 상태를 함께 보는 습관을 만들었습니다. Linux 기반 고객 환경을 지원할 때 원인을 시스템 계층까지 추적하는 데 도움이 됩니다.

SysY 언어 컴파일러 프론트엔드 & VM

2024.10 – 2025.01 · 1인 개발
C++17 · Lexer / Parser / Symbol Table / P-Code VM · CMake · Fault-Tolerant Parser

SysY 언어의 Lexer, 재귀 하향 Parser, Symbol Table, P-Code VM 전 과정을 C++17로 구현했습니다. 장애 대응과 직접 같은 영역은 아니지만, 잘못된 입력에서도 상태를 잃지 않는 구현 원칙을 익힌 프로젝트입니다.

구현
  • 재귀 하향 파서와 스코프 체인 기반 심볼 테이블을 구현해 중복 선언, 미정의 식별자, 함수 시그니처 불일치 등을 진단했습니다.
  • CMake 기반으로 Lexer, Parser, SymbolTable, ErrorHandler, Interpreter를 모듈 단위로 정리했습니다.
문제

세미콜론 누락 에러 복구 시 토큰 포인터가 과도하게 이동해 정상 구문까지 연쇄적으로 오류로 판정하는 문제가 발생했습니다.

해결

에러를 파싱 중단 사유가 아니라 문맥 복귀 신호로 재정의하고, 직전 유효 토큰 위치인 mLastNonT를 기록해 정상 흐름으로 복구하도록 개선했습니다.

연결

정상 입력뿐 아니라 비정상 입력에서도 상태를 보존하는 설계는 고객 환경 장애 대응에도 중요합니다. 문제를 중단이 아니라 복구 가능한 상태로 다루는 관점을 얻었습니다.

AI · PRODUCTARCHITECTURE

React Native 앱, Spring Boot 데이터·인증 계층, FastAPI ECG 추론 계층을 책임 단위로 분리한 헬스케어 플랫폼입니다.

캐시 읽기 평균 0.29ms · 네트워크 동기화 평균 603.97ms

Contribution

  • 모바일 앱이 AI 서버를 직접 호출하던 흐름을 Spring Boot 프록시 경유 구조로 바꿔 인증·검증을 중앙화했습니다.
  • AsyncStorage 캐시를 먼저 표시하고 서버 데이터를 후방 동기화해 네트워크 대기와 첫 화면 표시를 분리했습니다.
  • 12-lead ECG 전처리와 CNN-CBAM-GRU 추론 경로를 측정해 CPU 병목을 BiGRU 연산과 필터링으로 좁혔습니다.

측정으로 데이터 흐름을 바꾸다

carelink_measured_metrics.json의 측정 시나리오에서 로컬 캐시 읽기 평균 0.29ms, 네트워크 동기화 평균 603.97ms를 기록했습니다. ECG 100요청은 별도 시나리오에서 성공률 100%, 평균 2,396.58ms였습니다.

13개 오류 범주 복구 · 3,598줄 단일 파일을 7개 책임 모듈로 분리

Contribution

  • 존재하지 않는 세미콜론·괄호를 보고해야 하는 i/j/k 오류에서 토큰을 소비하지 않는 복구 흐름을 설계했습니다.
  • 에러 기록만 하던 함수를 bool 반환 계약으로 바꾸고 호출 사슬 전체에 실패를 전파해 후속 연쇄 오진을 차단했습니다.
  • Lexer, Parser, ErrorHandler, SymbolTableManager, Interpreter와 공통 자료구조를 분리하고 CMake 빌드 구조로 정리했습니다.

호출 그래프를 다시 그려 제어 흐름을 추적하고, 오류 우선순위와 후속 의미 검사의 경계를 재설계했습니다. 공개·비공개 테스트 만점으로 결과를 검증했습니다.

03
SEARCHDATA

논문·특허·수상·연구자·기관 데이터를 통합하고 전문·벡터 검색과 AI 분석을 결합한 학술 데이터 플랫폼입니다.

조회 API 평균 7–9ms · 오류율 0% / 조건 검색 P95 2.44초 병목 식별

Design focus

  • PostgreSQL을 정본으로, Elasticsearch를 다국어 전문·벡터 검색용 조회 모델로 분리했습니다.
  • 임베딩을 만들 수 없을 때 BM25로 폴백하고, LLM이 만든 조건은 DB의 실제 허용값으로 다시 검증했습니다.
  • OpenAlex 적재를 큐·worker로 분리하고 Redis TTL 캐시와 조회수 write-behind 구조를 분석했습니다.

빠른 경로와 느린 경로를 분리하다

동시 사용자 20명 벤치마크로 공개·분석 조회의 안정성을 확인하고, 조건 검색의 동기 벡터 호출과 후보 수를 병목 후보로 구체화했습니다.

04
LOW LEVELMIPS

7단계 lab과 변형 브랜치를 추적하며 부팅부터 메모리·프로세스·COW·IPC·파일 시스템·shell까지 실행 흐름을 구조화했습니다.

7 Labs · 64MB 메모리 모델 · 4KB 페이지 / 블록

Analysis scope

  • MIPS 부팅, 페이지 할당, 2단계 페이지 테이블과 소프트웨어 TLB refill 흐름을 추적했습니다.
  • 커널 primitive와 user-level page fault handler를 조합하는 COW fork 및 IPC 구조를 정리했습니다.
  • 사용자 공간 파일 서버, 공유 페이지 기반 pipe, redirection과 shell이 같은 fd 추상화로 연결되는 과정을 분석했습니다.

작은 커널 primitive에서 제품 기능까지

커널이 모든 기능을 제공하는 대신 페이지 매핑·환경 생성·IPC를 제공하고, user space에서 fork·FS·pipe·shell을 조립하는 설계를 전체 흐름으로 이해했습니다.

CareLink — React Native 모바일 보험형 헬스케어 UX

2025.10 – 2026.03 · 1인 개발 / 졸업논문
React Native · 모바일 UI · JWT 인증 · Cache-First · Spring Boot / FastAPI API 연동 · 평균 첫 표시 0.29ms

환자와 보호자를 연결하는 모바일 앱을 React Native로 구현하고, Spring Boot 백엔드와 FastAPI AI 추론 서버를 연동했습니다. 사용자가 진단 결과를 빠르게 확인할 수 있도록 인증 상태, 캐시, 네트워크 동기화 흐름을 함께 설계했습니다.

구현
  • React Native 모바일 클라이언트에서 환자/보호자 역할별 화면 흐름을 구성하고, 백엔드 API 응답에 따라 진단 결과와 사용자 상태를 갱신했습니다.
  • JWT 만료 시 자동 로그아웃 흐름을 구현하고, AsyncStorage 기반 Cache-First 전략으로 홈 화면 첫 표시 평균 0.29ms, 네트워크 동기화 평균 604.3ms를 기록했습니다.
  • 모바일 메모리 부담을 줄이기 위해 AI 추론은 서버 사이드에서 수행하고, 앱은 백엔드 프록시를 통해 결과만 전달받도록 구조를 분리했습니다.
문제

초기 구조에서는 추론 지연과 모바일 환경의 자원 부담이 커서 실시간 모니터링 UX에 바로 적용하기 어려웠습니다.

해결

모델 업데이트 유연성과 모바일 성능을 위해 서버 사이드 추론 방식을 채택했습니다. 모바일은 결과 조회와 상태 표현에 집중하고, 무거운 연산은 FastAPI 서버에서 처리하도록 역할을 분리했습니다.

연결

bolttech의 웹·모바일 보험 플랫폼에서도 상품 가입, 보상 안내, 디바이스 보호 상태처럼 사용자가 즉시 이해해야 하는 화면에 빠른 로딩과 명확한 상태 표현을 적용할 수 있습니다.

학술 성과 공유 플랫폼 — Vue 3 웹/API 통합

2025.03 – 2025.08 · Backend / Full-Stack
Vue 3 · TypeScript · Vite · Spring Boot API · 프론트-백엔드 인터페이스 · API 파싱 오류 0건

Vue 3 기반 SPA와 Spring Boot, PostgreSQL, Elasticsearch, Redis, MinIO를 연동한 학술 성과 검색 플랫폼입니다. 백엔드를 전담하면서도 Vue 3 + TypeScript + Vite 환경과의 API 통신 구조를 설계하고 프론트-백엔드 인터페이스를 통합했습니다.

구현
  • 검색, 상세 조회, 분석, 외부 메타데이터 연동 기능을 갖춘 플랫폼에서 API 응답 구조와 프론트엔드 데이터 흐름을 맞췄습니다.
  • Vue 3 화면이 안정적으로 데이터를 렌더링할 수 있도록 공통 응답 규약과 에러 메시지 구조를 정의했습니다.
  • Docker Compose 통합 환경과 README/RFC 문서화를 통해 팀원이 동일한 개발 환경에서 화면/API를 검증할 수 있도록 했습니다.
문제

개발자마다 API 응답 구조가 달라 프론트엔드에서 파싱 오류가 반복됐습니다. 문서화와 구두 합의만으로는 휴먼 에러가 재발했습니다.

해결

Spring의 ResponseBodyAdvice로 모든 컨트롤러 반환값을 {code, message, data} 구조로 자동 래핑했습니다. 그 결과 프론트엔드 파싱 오류를 0건으로 수렴시켰습니다.

협업

Vue vs React, Huawei Cloud vs AWS 선택 이견이 있을 때 더미 데이터 10만 건으로 응답 속도를 비교해 합의를 이끌었습니다. 애자일 팀에서 요구사항과 기술 선택을 주도적으로 조율한 경험입니다.

주요 프로젝트를 한국어, 영어, 중국어로 설명하는 웹 포트폴리오를 구현했습니다. 여러 프로젝트의 긴 기술 설명을 사용자가 단계적으로 탐색할 수 있도록 내비게이션, 섹션 전환, 프로젝트 아코디언 구조를 설계했습니다.

구현
  • 데스크톱/모바일 내비게이션과 drawer 메뉴를 구성해 작은 화면에서도 프로젝트 섹션에 접근할 수 있도록 했습니다.
  • 프로젝트별 아키텍처, 트러블슈팅, 성능 수치를 접었다 펼치는 구조로 배치해 긴 내용을 스캔 가능한 UI로 바꿨습니다.
  • 한국어/영어/중국어 텍스트 매핑을 구성해 글로벌 기업 지원 시 언어별 메시지를 일관되게 관리할 수 있도록 했습니다.
문제

해결

요약 카드, 프로젝트 상세, 트러블슈팅 패널을 분리하고 사용자가 필요한 깊이만 열람하도록 구성했습니다. 보험 상품 설명처럼 정보량이 많은 화면에서도 단계적 노출 전략을 적용할 수 있습니다.

품질

텍스트 줄바꿈, 섹션 간 간격, 모바일 drawer 상태를 확인하며 다양한 화면 폭에서 콘텐츠가 겹치지 않도록 조정했습니다.

SysY 언어 컴파일러 — 예외 상태에 강한 파서 구현

2024.10 – 2025.01 · 1인 개발
C++17 · Parser State · Error Recovery · Symbol Table · CMake · 견고한 상태 관리

SysY 언어의 Lexer, 재귀 하향 Parser, Symbol Table, P-Code VM을 C++17로 구현했습니다. 프론트엔드 프로젝트는 아니지만, 복잡한 상태와 비정상 입력을 안정적으로 처리하는 사고를 기른 프로젝트입니다.

구현
  • 토큰 스트림을 기반으로 선언문, 표현식, 함수 호출, 제어문을 분석하고, 심볼 테이블로 중복 선언과 함수 시그니처 불일치를 진단했습니다.
  • CMake 기반으로 Lexer, Parser, SymbolTable, ErrorHandler, Interpreter를 모듈 단위로 분리했습니다.
문제

세미콜론 누락 같은 작은 구문 오류가 발생했을 때 토큰 포인터가 과도하게 이동해 정상 구문까지 연쇄적으로 오류로 판정했습니다.

해결

에러를 파싱 중단 사유가 아니라 문맥 복귀 신호로 재정의하고, 직전 유효 토큰 위치인 mLastNonT를 기록해 정상 흐름으로 복구했습니다.

연결

프론트엔드에서도 사용자의 비정상 입력, API 실패, 부분 로딩 상태를 중단이 아니라 복구 가능한 상태로 다루어야 합니다. 이 프로젝트를 통해 예외 상태를 보존하고 회복하는 구현 감각을 익혔습니다.
